# devNepal

devNepal is being built to connect volunteers with open-source government software projects in Nepal. The aim is to make useful work easier to find, give contributors a clear way to take part, and help public institutions maintain software with support from the wider community.

Contributions can include software development, design, documentation, testing, accessibility, translation, and research. Each project should explain the public need it serves, the help it needs, and who is responsible for reviewing the work.

## Who devNepal is for

- **Volunteer contributors** who want to use their skills, learn through practical work, and support public services.
- **Government teams and maintainers** who want to open suitable projects to contribution and guide the people working on them.
- **The public** who want to understand what is being built, follow its progress, give feedback, and suggest improvements.

## How participation will work

Only authorised government bodies will be able to create projects on devNepal. New listings will first invite applications from volunteers willing to lead the initial design and development. SDOC will select applicants based on their experience. The founding team will include at least one representative of the government office that will use the software to clarify business processes and resolve blockers, and at least one SDOC representative acting as administrator on its behalf.

The team will establish a clear, maintainable foundation. Selected technical leads who demonstrate good work will be recognised by SDOC as maintainers. Once the foundation is ready, the team will prepare issues for defined milestones and open the project to public contribution. Each listing will make its current stage and participation instructions clear.

People will be able to join devNepal using email, GitHub, Google, Facebook, or other supported sign-in services. Members will be able to comment and give feedback on devNepal without a GitHub connection. Taking part as a developer or repository contributor through devNepal will require a connected GitHub account. Source code, repository issues, pull requests, and reviews will remain on GitHub.

devNepal will index public contributions to participating GitHub repositories independently of account creation. Contributing on GitHub will not require a devNepal account or automatically create one. If you later sign in with or connect the GitHub account used for that work, devNepal will show you its already indexed contribution history after verifying that you control the account.

Member profiles will require SDOC approval before appearing in the public directory. Indexed contribution records and public member profiles are separate. The [privacy notice](PRIVACY.md) explains account information, profile visibility, and personal controls.

Over time, devNepal will help connect project information, contributor activity, and accepted work so that people can follow a project's progress and find their next contribution.

## Development status

The platform is under development. This repository currently contains public documentation; application code and local development instructions are not yet included. The planned features below describe the intended direction.

## Hosting and oversight

All devNepal hosting will use Government of Nepal facilities, without exception. This covers the application, databases, file storage, and backups. GitHub collaboration and external sign-in services operate separately from devNepal's hosting.

SDOC oversees confidential operations and access to private information. Public repository roles do not themselves grant access to that information.

## Planned features

- **Project discovery:** projects created by authorised government bodies, with clear outcomes, ownership, progress updates, and a visible stage from founding-team recruitment to public contribution.
- **Founding teams:** applications assessed by SDOC, technical leadership supported by government office and SDOC representatives, and maintainer recognition based on demonstrated work.
- **Member accounts and profiles:** multiple sign-in options, self-service profile editing and deletion, SDOC approval for public profiles, and verified GitHub connections for developers and repository contributors.
- **Platform participation:** member comments and feedback through devNepal, without requiring GitHub for those activities.
- **Contribution history:** index GitHub contributions independently of membership and connect existing records when a member verifies the relevant GitHub account.
- **Project management:** explore project and milestone views in devNepal with GitHub synchronization; repository issues remain on GitHub for now.
- **Contribution recognition:** a record of work accepted by maintainers, including design, documentation, testing, and other contributions alongside code.
- **Community knowledge:** technical writing and practical guidance drawn from project work.
- **Language and accessibility:** support for English and Nepali, accessible interaction, and pages that work well on phones and slower connections. Current documentation work is in English; Nepali is planned.

## Contributing

Start with [CONTRIBUTING.md](CONTRIBUTING.md). It explains how to propose work, keep a contribution focused, and prepare it for review. Use the repository's GitHub Issues tab for public questions and tasks.

For a project listed on devNepal, follow that project's own contribution guide. Its maintainers decide what work is in scope and whether a contribution is accepted.

## Project principles

Work should address a clear public need. Projects should have maintainers who can guide contributors, review submissions, and explain decisions. Contributions should be credited for the work accepted, including work that does not involve code.

Public collaboration also requires care with information. Projects must be suitable for public contribution, and public repositories must exclude credentials, private personal information, and restricted government material.
